# 蓝桥杯嵌入式 · 第 15 届省赛「双通道脉冲测量系统」

基于 **CT117E-M4（STM32G431RBT6）** 的练习工程，CubeMX + HAL 库 + Keil MDK 开发。
这是备赛期间的第一套真题练习，代码在 AI 助手辅助下完成，用作学习记录，也希望能给同样备赛的同学一点参考。

---

## 一、实现功能

| # | 功能 | 说明 |
|---|---|---|
| 1 | 双通道频率测量 | 输入捕获，量程 400 Hz ~ 20 kHz，0.1 s 刷新 |
| 2 | PX 校准 | `f_cal = f + PX`，校准值用于显示、周期换算、突变与超限判定 |
| 3 | 频率 / 周期显示切换 | 数据界面短按 B3 切换；周期 > 1000 uS 显示 mS |
| 4 | 突变检测 | 3 秒窗口内 `max - min > PD` 计一次，分块结算 |
| 5 | 超限检测 | `f_cal > PH` 时边沿触发计数，避免反复累加 |
| 6 | LED 指示 | LD1 数据界面 / LD2 A 超限 / LD3 B 超限 / LD8 突变≥3 |
| 7 | 三界面切换 | DATA / PARA / RECD，B4 循环切换 |
| 8 | 参数调节 | B1 +100、B2 -100、B3 在 PD/PH/PX 之间切换 |
| 9 | 记录清零 | 记录界面长按 B3 超过 1 秒后松开清零，短按无效 |

### 参数范围

| 参数 | 范围 | 默认值 | 含义 |
|---|---|---|---|
| PD | 100 ~ 1000 Hz | 1000 | 突变判定阈值 |
| PH | 1000 ~ 10000 Hz | 5000 | 超限判定阈值 |
| PX | -1000 ~ 1000 Hz | 0 | 频率校准偏移量 |

## 二、硬件与引脚分配

| 功能 | 引脚 | 配置 |
|---|---|---|
| A 通道脉冲输入 | PA15 | TIM2_CH1 输入捕获，预分频后 1 tick = 1 us |
| B 通道脉冲输入 | PB4 | TIM3_CH1 输入捕获，同上 |
| B1 ~ B4 按键 | PB0 / PB1 / PB2 / PA0 | GPIO 输入，按下为低电平 |
| LD1 ~ LD8 | PC8 ~ PC15 | GPIO 推挽输出 |
| LED 锁存 | PD2 | 74HC573 的 LE，写完数据后给一个上升沿 |
| 1 ms 时基 | TIM6 | 中断里 `xms++` |
| LCD | — | 官方 `lcd.c` 驱动 |

> **信号源说明**：CT117E-M4 板载两个 NE555 信号发生器（旋钮 R39 / R40，跳线帽 J9 / J10），
> 输出经跳线帽接到 PA15、PB4，实测范围约 630 Hz ~ 22.4 kHz，正好覆盖题目要求。
> 测试时需要确认 J9 / J10 已插好，否则引脚悬空、读数为 0。

## 四、编译与烧录

1. 安装 **Keil MDK-ARM 5.2x**，并装好 `Keil.STM32G4xx_DFP` 器件支持包

## 五、几个实现上的取舍

**1. 突变检测用极值法，不用数组**

题目要求 3 秒窗口内的最大最小值之差。常见做法是开 30 个点的环形数组存 100 ms 采样，
这里改成只记 `max` / `min` 两个变量，每 3 秒结算一次并重置：

```c
if(fA_cal>fA_max) fA_max=fA_cal;
if(fA_cal<fA_min) fA_min=fA_cal;
if(xms-fA_3swindow>=3000)
{
    if(fA_3swindow!=0 && fA_max-fA_min>PD) NDA++;
    fA_max=fA_cal; fA_min=fA_cal; fA_3swindow=xms;
}
```

代价是**分块窗口可能漏掉跨越结算点的跳变**，换来的是 6 行代码和省下的 240 字节 RAM。

**2. 长按清零不需要锁标志**

`Key_scan()` 返回的是 **keyup**（松手），一次按下只在松手瞬间返回一次，
所以"按满 1 秒后松手清零"天然只触发一次，不需要 `key_longkeep` 这类锁。

**3. 超限计数需要边沿检测**

超限判定在主循环里每圈都执行，如果直接 `if(f>PH) NHA++`，1 秒能加几百次。
必须用一个 `over_A` 标志做边沿检测：

```c
if(fA_cal>(int32_t)PH)
{
    if(over_A==0){ NHA++; over_A=1; }
}
else over_A=0;
```

**4. 有符号比较必须强转**

`fA_cal` 是 `int32_t`，`PH` 是 `uint32_t`。PX 调到负数时 `fA_cal` 可能为负，
直接比较会被当成 42 亿，导致 LD2 误亮、NHA 误加。

## 六、已知问题

- 突变检测采用分块窗口，**跨越 3 秒结算点的跳变会漏检**
- 周期显示用 `1000000/f_cal` 取整，低频率时末位有 ±1 uS 误差
- `main.c` 中 LED 判定与超限判定共 5 处 `fA_cal>PH` 未加 `(int32_t)` 强转，PX 为负时可能误判
- 按键驱动里 `Key_scan` 直接处理了 B3 长按计时，属于业务逻辑混入驱动层；
  通用模板应改成 `Key_longpress(0x04)` 之类的接口
